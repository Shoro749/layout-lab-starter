AI-агент тут виступає у двох ролях: спочатку генерує рішення, потім перевіряє його як reviewer. Між цими етапами ви перевіряєте код самостійно.

Етап 1. Генерація. Отримайте від AI-агента CSS-рішення для такого завдання:

Create a responsive dashboard with a header, sidebar, main content area and a grid of cards. It should work on desktop, tablet and mobile.

Покладіть відповідь AI без змін у challenge-09/original/, а виправлену версію — у challenge-09/final/, щоб наприкінці порівняти початковий і фінальний CSS.

Етап 2. Власна перевірка. Перевірте рішення у DevTools і самостійно знайдіть щонайменше 3 потенційні проблеми або зайві рішення. Зверніть увагу на надмірну кількість Media Queries, фіксовані ширини, min-width, overflow, дублювання CSS, неправильне використання Flexbox/Grid, можливість використати minmax()/auto-fit та Container Query.

При власній перевірці ніяких проблем не знайшов.

Етап 3. AI code review.

  1. Передайте згенерований код AI-агенту з prompt-ом для code review (§7 лабораторної).
  2. Перевірте кожну рекомендацію AI за MDN/web.dev і порівняйте з власною перевіркою: що знайшов AI, а що — ви.
  3. Виправте обґрунтовані проблеми.
  4. Порівняйте початковий і фінальний CSS.
AI-рекомендація Прийнята? Перевірка Обґрунтування
Прибрати overflow: hidden з .main-content. Так MDN overflow: hidden може обрізати контент, який виходить за межі контейнера. Для основного контенту безпечніше не приховувати потенційне переповнення.
Зменшити залежність .content-grid від фіксованого мінімуму 300px для другої колонки. Так MDN minmax() використовується правильно, але minmax(300px, .85fr) встановлює досить жорстку мінімальну ширину. Використання minmax(0, .85fr) робить grid гнучкішим.
Замінити auto-fit у .stats-grid на додаткові media queries. Ні MDN / web.dev Поточний repeat(auto-fit, minmax(...)) вже є хорошим responsive-рішенням. Grid автоматично підбирає кількість колонок, тому додаткові breakpoint-и тут лише ускладнять CSS.
Прибрати фіксовану ширину sidebar 224px. Ні MDN Фіксована ширина sidebar є прийнятною для desktop layout. На екранах до 760px sidebar змінює структуру і переходить у горизонтальну навігацію, тому проблема не є критичною.
Додати більше media queries для кожного типу екрану. Ні MDN / web.dev У коді вже є два breakpoint-и — 760px і 420px, які відповідають реальним змінам layout. Додавання великої кількості breakpoint-ів зробило б CSS складнішим без очевидної користі.
